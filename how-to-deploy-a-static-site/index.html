How to deploy a static site for $0 (GitHub Pages)

A static site is HTML, CSS, and maybe JavaScript files. No PHP. No database. You can put it on GitHub Pages at $0, with no custom domain and no hosting invoice. DNS is a later chapter.

Who this is for

Students and small-site owners who need a public URL for a portfolio, a class page, or this kind of comparison site. If you need WordPress, Laravel, or MySQL, stop: that is not static. Use beginner hosting criteria or shared vs managed cloud instead.

What static means here

The server copies files to the browser. It does not run your code on each request. Forms that email you, login sessions, and shopping carts need something else (or a third-party form backend you are willing to trust — out of scope here).

Before you touch DNS

Do not buy a domain to feel professional on day one. GitHub will give you a *.github.io hostname. Get the site green on that name first. Pointing a domain is a separate, optional step (and it is how people accidentally produce a blank site for 24 hours).

Tutorial: GitHub Pages from the repo root

Official product page: https://pages.github.com/. Official docs live under GitHub Docs. UI labels change; if a blog screenshot disagrees with GitHub docs, trust the docs.

  1. Use a GitHub account you already have (signup is GitHub product, not Host Intent). This tutorial does not require paid GitHub features for a public project site — confirm on GitHub current billing docs if your repo is private.
  2. Create a new repository in the GitHub UI. Public repos can use Pages as GitHub currently documents.
  3. Add your files. A minimal site is index.html plus CSS. Folder URLs work if each folder has index.html (the same pattern this Host Intent tree uses).
  4. Commit on a branch you control. GitHub currently documents deploying from a branch (often the default branch) or from a /docs folder. This Host Intent source tree is meant to attach later as root or docs/ — see the project README. Follow your own branch policy; this site source prefers a branch named site if you init git locally.
  5. Enable Pages in the repository Settings, Pages section. Choose the branch and / or /docs. Save.
  6. Wait for the first build. GitHub shows a https://USER.github.io/REPO/ URL for project sites. User/organization sites use a different repo-name rule; read official docs rather than guessing.
  7. Check relative URLs. Open the Pages URL on a phone. If CSS 404s, your stylesheet path was probably absolute (/css/style.css) instead of relative. This tree uses relative paths so it also works when you open files locally.

Preview locally before you publish

You can open index.html in a browser. For folder links, a local static server is cleaner. From this site directory:

python3 -m http.server 8080

Then visit http://127.0.0.1:8080/. No Node toolchain is required for Host Intent.

Optional: docs folder vs root

GitHub Pages can serve the repository root or a docs/ folder on a branch. If your git repo also holds notes that must not go public, keep the public HTML in docs/ and point Pages there. Host Intent files currently live as a standalone tree (see project README). This site is the worked example: https://luiyi0905.github.io/host-intent/ on branch site.

Custom domains (later)

When you actually own a domain, GitHub docs describe a CNAME file and DNS records at your registrar. Namecheap is one registrar; official site: Namecheap. Wrong records fail closed. Do this on a weekend, not an hour before class.

When to leave Pages for a paid host

  • You need server-side PHP or a database.
  • You need mailbox hosting on the same vendor (still optional — school email may be enough).
  • Your app is not static. Then use the beginner or managed cloud pages.

FAQ

Does GitHub Pages support HTTPS?
GitHub documents HTTPS for Pages hostnames. Enforce it in the Pages settings when the checkbox is available. Custom domains have extra DNS/HTTPS steps in the official docs.
Can I use a tiny SSG?
Yes, if it emits static files. This Host Intent tree is already plain HTML so you can preview without installing a framework.
Is this an affiliate tutorial to sell hosting?
