How to deploy a static site for $0 (GitHub Pages)

A static site is HTML, CSS, and maybe JavaScript files. No PHP. No database. You can put it on GitHub Pages at $0, with no custom domain and no hosting invoice. Host Intent itself is the worked example: a live project site at https://luiyi0905.github.io/host-intent/ (source on branch site). DNS is a later chapter.

Who this is for

Students and small-site owners who need a public URL for a portfolio, a class page, or this kind of comparison site — including operators copying this exact tree (branch site, relative URLs, .nojekyll). If you need WordPress, Laravel, or MySQL, stop: that is not static. Use beginner hosting criteria, student hosting, or shared vs managed cloud instead. You do not need to buy a domain on day one.

What static means here

The server copies files to the browser. It does not run your code on each request. Forms that email you, login sessions, and shopping carts need something else (or a third-party form backend you are willing to trust — out of scope here).

Project site vs user/organization site

GitHub documents two shapes. A project site lives at https://USER.github.io/REPO/. Host Intent is that shape: luiyi0905.github.io/host-intent/. A user or organization site uses a different repository-name rule and a different default URL. Read the official overview rather than guessing: What is GitHub Pages?.

Before you touch DNS

Do not buy a domain to feel professional on day one. GitHub will give you a *.github.io hostname. Get the site green on that name first. Pointing a domain is a separate, optional step (and it is how people accidentally produce a blank site while DNS propagates). If you later buy a domain only, see Namecheap hosting vs Hostinger for the “domain without hosting” fork — still optional for this tutorial.

Tutorial: GitHub Pages from the repo root

Official product page: https://pages.github.com/. Docs hub: https://docs.github.com/en/pages. Quickstart: Pages quickstart. UI labels change; if a blog screenshot disagrees with GitHub docs, trust the docs.

  1. Use a GitHub account you already have (signup is GitHub product, not Host Intent). This tutorial does not require paid GitHub features for a public project site — confirm on GitHub’s current billing docs if your repo is private.
  2. Create a new repository in the GitHub UI. Public repos can use Pages as GitHub currently documents. Creating a site: Creating a GitHub Pages site.
  3. Add your files. A minimal site is index.html plus CSS. Folder URLs work if each folder has index.html (the same pattern this Host Intent tree uses). Include an empty .nojekyll file at the publishing root so Pages does not run Jekyll on plain HTML (GitHub documents this when you are not using Jekyll).
  4. Commit on a branch you control. GitHub lets you publish from a branch (root / or /docs) or via Actions — see Configuring a publishing source. Host Intent’s policy is branch site + repository root (/). That is our convention, not a GitHub requirement.
  5. Enable Pages in the repository Settings → Pages. Choose Deploy from a branch, select your branch and / or /docs, then Save.
  6. Wait for the first build. GitHub shows a https://USER.github.io/REPO/ URL for project sites. First publishes can take a few minutes; if nothing appears after a longer wait, check the docs’ build/troubleshooting notes rather than inventing a timeout.
  7. Check relative URLs. Open the Pages URL on a phone. If CSS 404s on https://user.github.io/repo/, your stylesheet path was probably site-root absolute (/css/style.css) instead of relative (css/style.css or ../css/style.css from a subfolder). Absolute paths that start with / resolve to https://user.github.io/css/… and miss the repo subpath. Host Intent uses relative paths so local preview and project Pages both work.

Preview locally before you publish

You can open index.html in a browser. For folder links, a local static server is cleaner. From this site directory:

python3 -m http.server 8080

Then visit http://127.0.0.1:8080/. No Node toolchain is required for Host Intent.

Optional: docs folder vs root

GitHub Pages can serve the repository root or a docs/ folder on a branch. If your git repo also holds notes that must not go public, keep the public HTML in docs/ and point Pages there. Host Intent publishes from branch site at root. Live example: https://luiyi0905.github.io/host-intent/.

HTTPS

GitHub documents HTTPS for Pages hostnames, including enforcement in repository Settings → Pages. Read Securing your GitHub Pages site with HTTPS. Custom-domain certificates have extra DNS steps in those docs. Do not freeze GitHub A/AAAA IP addresses into this page — copy current values from GitHub’s custom-domain docs the day you do DNS.

Custom domains (later)

When you actually own a domain, GitHub docs describe DNS records and (when needed) a CNAME file: About custom domains and GitHub Pages and Managing a custom domain. Namecheap is one registrar; official tracked link: Namecheap. Registrar DNS help (if you use Namecheap): How to change DNS for a domain. Wrong records fail closed. Do this on a weekend, not an hour before class. Propagation can take a while; we do not invent an “always 24 hours” promise.

Optional: custom 404 page

You may add a 404.html at the publishing root so visitors see a friendlier page when a path is missing. Treat it as a normal static file; check current GitHub Pages docs for any Jekyll-related notes if you are not using .nojekyll.

Troubleshooting (short)

  • First build delay. Wait a few minutes after enabling Pages or pushing; then hard-refresh. Check Actions / Pages status in the repo if nothing appears.
  • 404 on a folder. Each public folder needs an index.html (or an explicit filename in the URL).
  • CSS or assets 404 on a project site. Relative paths vs leading-slash absolute paths — see the relative-URL step above.
  • Wrong branch selected. Settings → Pages must point at the branch and folder you actually push (for Host Intent: site + /).
  • Mixed content after a custom domain. Assets still loading over http:// break HTTPS pages — fix asset URLs per GitHub’s HTTPS doc.
  • Limits and private repos. Quotas and private-repo billing change; read GitHub Pages limits and GitHub billing docs rather than numbers copied here.

When to leave Pages for a paid host

  • You need server-side PHP or a database.
  • You need mailbox hosting on the same vendor (still optional — school email may be enough).
  • Your app is not static. Then use the beginner, students, or Hostinger vs Cloudways pages.

FAQ

Does GitHub Pages support HTTPS?
Yes for correctly configured Pages hostnames, as documented. Enforce it in Pages settings when the checkbox is available. Custom domains have extra DNS/HTTPS steps in the official docs linked above.
Can I use a tiny SSG?
Yes, if it emits static files. This Host Intent tree is already plain HTML so you can preview without installing a framework. If you skip Jekyll, keep .nojekyll as GitHub documents.
Is this an affiliate tutorial to sell hosting?
No. The point is you may not need paid hosting yet. Paid-host links stay in the official-links list for when Pages is the wrong shape. Disclosure: About.
